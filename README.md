# Qwiz Platform

Flask + Oracle. Для работы приложения нужен Python 3.9+ и доступ к Oracle Database.

## Инструкции для запуска и тестирования

- [Пошаговая инструкция без Docker](docs/START_HERE_RU.md): Python на Windows/macOS/Linux, подключение к готовой Oracle, локальная установка Oracle Free на поддерживаемой ОС, роли и работа с тестами.
- [Чек-лист тестирования](docs/TEST_CHECKLIST_RU.md): сценарии с ожидаемыми результатами, автоматические проверки и шаблон сообщения об ошибке.

Начните с первой инструкции, если получили проект впервые. Файлы из `templates` не открывают напрямую: работающий сайт доступен через HTTP. В инструкциях используется порт **5063**.

Основной сценарий для проверяющего: получить параметры готовой схемы Oracle, установить Python-зависимости и запустить Flask. Docker не нужен. Доступная Oracle всё равно обязательна; DBeaver — только клиент для её настройки. На macOS используйте Oracle на другом компьютере/сервере.

## Обновление существующего проекта

1. Остановите приложение и установите зависимости: `pip install -r requirements.txt`.
2. В DBeaver подключитесь **под тем же пользователем, что указан в DB_USER приложения**.
3. Откройте `sql/10_upgrade_workflow.sql` в кодировке UTF-8 и выполните целиком как SQL Script (`Alt+X`). Включите остановку при ошибке в настройках выполнения скриптов. Скрипт добавляет таблицу таймеров, исправляет последовательности справочников и пересоздаёт пакет. Пользователи, тесты и результаты сохраняются. Его можно выполнять повторно при остановленном приложении.
4. В конце скрипта обе строки `QUIZ_PLATFORM` должны иметь статус `VALID`, а выборка ошибок должна быть пустой.
5. Выполните `python manage.py check-db`, затем `python -m flask --app app run --host 127.0.0.1 --port 5063`.

Не используйте `08_seed_test_data.sql` или `99_drop_all.sql` для обновления: они удаляют данные.

## Новая установка

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

На macOS/Linux окружение активируется командой `source .venv/bin/activate`.

Создайте отдельного пользователя Oracle с правами на таблицы, последовательности, триггеры и пакеты. В его **пустой схеме** выполните `sql/00_install_all.sql` целиком. Не запускайте установку под `SYSTEM`: приложение обращается к объектам своей схемы. Установщик не удаляет существующие таблицы; для уже установленной БД используйте обновление выше.

Для SQL*Plus укажите UTF-8: в PowerShell `$env:NLS_LANG=".AL32UTF8"`, в macOS/Linux `export NLS_LANG=.AL32UTF8`. Затем подключитесь под пользователем приложения и выполните `@sql/00_install_all.sql`. Перед запуском в SQL*Plus можно включить `WHENEVER SQLERROR EXIT FAILURE ROLLBACK`, чтобы остановиться на первой ошибке.

Переменные подключения (подставьте свои значения):

```powershell
$env:DB_USER="имя_пользователя_Oracle"
$env:DB_PASSWORD="пароль_Oracle"
$env:DB_DSN="адрес:1521/имя_сервиса"
$env:SECRET_KEY="произвольная-длинная-строка"
python manage.py check-db
python -m flask --app app run --host 127.0.0.1 --port 5063
```

На macOS/Linux вместо `$env:NAME="value"` используйте `export NAME="value"`.
Откройте `http://127.0.0.1:5063`.

## Как проверить работу

1. Зарегистрируйтесь. Вход — по UID и паролю; UID виден после регистрации, в кабинете и профиле.
2. Первый пользователь **пустой БД** получает роль администратора. Он может назначать роли на странице «Админ: пользователи». Если в существующей БД администратора нет, назначьте его явно: `python manage.py make-admin UID`.
3. Под автором/администратором создайте категорию, затем вопрос. Для текстового/числового вопроса нужен эталон; для выбора — минимум два варианта с правильным ответом.
4. Создайте тест, добавьте вопросы вручную или автоматически, затем опубликуйте. Автогенерация использует только готовые вопросы текущего автора.
5. На странице доступа выдайте тест зарегистрированному пользователю по UID.
6. Под пользователем откройте «Доступные тесты» и начните попытку. Повторный старт продолжает текущую попытку. Пустой ответ не сохраняется; необязательный вопрос можно пропустить. Время на вопрос считается на сервере и не сбрасывается при обновлении страницы.
7. После обязательных вопросов завершите попытку. Результат и эталоны доступны только после завершения. Истечение общего времени автоматически завершает попытку с учётом сохранённых ответов.

Вопросы скрытого теста без попыток можно добавлять/удалять и генерировать заново. После первого прохождения состав фиксируется, чтобы не менять задания и оценки задним числом: для другой версии создайте новый тест. Варианты ответов нельзя менять, пока вопрос используется в опубликованном или уже пройденном тесте.

Администратор управляет тестами и вопросами всех авторов: составом, вариантами, публикацией, доступом и статистикой. Его банк вопросов и список управления показывают все объекты; автогенерация использует готовые вопросы всех авторов. Можно проходить любой готовый тест, включая скрытый, без отдельной выдачи доступа и ограничения количества попыток. Это обычные попытки: они учитываются в статистике и фиксируют состав теста. Раздел «Админ: все попытки» открывает попытки всех пользователей; администратор может продолжить и завершить незавершённую попытку, а после завершения видит ответы даже при отключённой обратной связи. На странице чужой попытки показывается предупреждение. Проверки готовности, таймеры и защита уже рассчитанных результатов действуют для всех ролей. Для применения этих прав к существующей базе повторно выполните `sql/10_upgrade_workflow.sql` при остановленном приложении.

Для отдельной демонстрационной БД можно выполнить `sql/08_seed_test_data.sql`: он **полностью очищает данные** и создаёт демонстрационные учётные записи, указанные в конце файла. Не применяйте его к рабочей базе.

## Автоматические проверки

Без Oracle:

```sh
python -m unittest discover -s tests -v
python scripts/build_sql.py --check
```

Полная проверка требует отдельной одноразовой схемы **QWIZ_TEST**, в которой выполнен установщик. Тесты удаляют записи приложения в этой схеме перед каждым сценарием. На macOS/Linux:

```sh
QWIZ_TEST_DSN="127.0.0.1:1521/FREEPDB1" QWIZ_TEST_PASSWORD="пароль_тестовой_схемы" python -m unittest discover -s tests -v
```

В PowerShell задайте эти две переменные через `$env:...`, затем выполните ту же команду Python.

Адрес в примере относится к локальной Oracle Free. Для удалённой базы замените его выданным `адрес:порт/имя_сервиса`.

Основные SQL-исходники — файлы `01`–`07` и `09`. После их изменения выполните `python scripts/build_sql.py`: он синхронизирует автономные установщик `00` и обновление `10`.
