# Qwiz: запуск и работа без Docker

Для человека, который впервые получил проект. Docker не требуется ни для запуска приложения, ни для описанной здесь подготовки базы. Здесь описана демонстрация и тестирование, а не публикация сервиса в интернете.

## 1. Что именно нужно запускать

Qwiz состоит из двух частей: веб-приложения на Python и базы Oracle. Обе должны работать одновременно. Одних HTML-файлов недостаточно.

Самый простой вариант для проверяющего: получить папку проекта и подключение к уже подготовленной Oracle, установить Python и выполнить разделы 2 и 5. Базу на компьютер проверяющего устанавливать не нужно. Если Oracle вообще нет, ответственный за установку сначала готовит её по разделам 3–4. Без доступной Oracle текущая версия приложения не работает: логика тестирования реализована в её SQL-пакете.

Открывать нужно **http://127.0.0.1:5063**, когда приложение запущено. Не открывайте файлы из папки `templates` двойным щелчком: так вы увидите `{{ ... }}`, `{% ... %}` и, возможно, испорченные русские буквы вместо сайта.

Адрес `127.0.0.1` означает компьютер, на котором открыт браузер. Отправить эту ссылку человеку на другом компьютере недостаточно: ему нужен собственный запуск по этой инструкции. Общий сетевой сервер здесь не настраивается.

### Выберите свой вариант

| Ситуация | Что делать |
|---|---|
| Приложение уже запущено для вас на этом компьютере | Откройте адрес выше и переходите к разделу 6. |
| Вам выдали подключение к готовой базе Qwiz | Разделы 2 и 5; подставьте выданные параметры. SQL-установку повторять не нужно. |
| Oracle есть, но Qwiz в ней ещё не установлен | Ответственный за базу выполняет разделы 3–4 в отдельной пустой схеме. Затем разделы 2 и 5 на компьютере проверяющего. |
| Oracle нет, нужен полностью локальный запуск | Раздел 3: установка Oracle Free на поддерживаемой Windows или Linux. На macOS используйте Oracle на другом компьютере/сервере. Затем разделы 4–5. |
| В базе установлена старая версия Qwiz | Раздел 8: обновление без удаления существующих данных. |
| Уже устанавливали проект и хотите включить его снова | Раздел 7: повторный запуск без переустановки и очистки данных. |

## 2. Подготовка компьютера и Python

Понадобятся:

- Папка проекта целиком: как минимум `app.py`, `db.py`, `manage.py`, `requirements.txt`, `templates`, `static`, `sql`, `scripts`, `tests` и `docs`.
- Python 3.9 или новее. Текущий проект проверялся с Python 3.14. Python скачивается с [официального сайта](https://www.python.org/downloads/).
- Браузер.
- Подключение к работающей Oracle: адрес, порт, имя сервиса, пользователь схемы и пароль. База может находиться на этом компьютере или на отдельном сервере.
- Для ответственного за установку схемы — [DBeaver Community](https://dbeaver.io/download/) либо уже имеющийся SQL-клиент. Если схема готова и нужен только запуск сайта, SQL-клиент необязателен. **DBeaver не является сервером Oracle и сам базу не создаёт.**
- Интернет для первой загрузки Python-зависимостей и, при необходимости, установщиков и драйвера DBeaver. Для удалённой Oracle — доступ к её сети/VPN.

Получите проект архивом или через Git. Если вам передали чужую папку `venv` или `.venv`, не используйте её: окружение создаётся на каждом компьютере отдельно.

Все команды ниже выполняются из папки проекта. Пути `C:\Projects\qwiz_platform_new` и `~/Projects/qwiz_platform_new` — примеры: замените их местом, куда вы распаковали проект. На Windows используйте **PowerShell**, на macOS/Linux — **Терминал**.

### Windows — PowerShell

```powershell
cd "C:\Projects\qwiz_platform_new"
py -3 --version
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Если команда `py` не найдена, но работает `python --version`, используйте `python` вместо `py -3` в первых двух командах Python.

### macOS / Linux — Терминал

```sh
cd "$HOME/Projects/qwiz_platform_new"
python3 --version
python3 -m venv .venv
./.venv/bin/python -m pip install -r requirements.txt
```

В этой инструкции Python вызывается прямо из `.venv`: активировать окружение отдельной командой не требуется. Дождитесь успешной установки зависимостей. Если установка завершилась ошибкой, сначала устраните её по разделу 10.

## 3. Подготовка Oracle без Docker

Этот раздел выполняет ответственный за базу **один раз**, не каждый проверяющий.

### Вариант А: Oracle уже есть — основной вариант

Получите у администратора базы:

- Адрес сервера и порт, например `1521`.
- **Имя сервиса** нужной базы. У новой Oracle Free обычно используется `FREEPDB1`; в существующей установке имя может быть другим.
- Отдельного пользователя схемы для Qwiz и его пароль либо возможность создать такую схему.
- Сведения о доступе по сети/VPN.

Не устанавливайте второй сервер Oracle, если нужная база уже работает. Для независимого тестирования попросите отдельную пустую схему, например `QWIZ_DEMO`. Если вам сразу выдали готовую схему с Qwiz, переходите к разделу 5. Если в ней старая версия — к разделу 8.

### Вариант Б: Oracle нет — локальная установка на Windows

1. Проверьте совместимость: установщик Oracle Free рассчитан на **Windows x64**, не Windows ARM; Windows Home не входит в поддерживаемые редакции. Для установки нужны права локального администратора. Проверьте также память и свободное место по [требованиям Oracle](https://docs.oracle.com/en/database/oracle/oracle-database/26/xeinw/requirements.html).
2. Скачайте Windows x64-установщик **Oracle AI Database Free** с [официальной страницы](https://www.oracle.com/database/free/get-started/). Не выбирайте Oracle Client вместо сервера базы.
3. Распакуйте архив, запустите `setup.exe` и пройдите мастер установки. Используйте предлагаемую новую папку установки, задайте и сохраните пароль служебных пользователей базы. Дождитесь успешного завершения.
4. Запишите показанное установщиком подключение к **pluggable database**. В стандартном локальном случае ниже используются хост `127.0.0.1`, порт `1521` и сервис `FREEPDB1`; если установщик показал другие значения, используйте их.

Подробности и ограничения мастера: [официальная инструкция установки на Windows](https://docs.oracle.com/en/database/oracle/oracle-database/26/xeinw/installing-oracle-database-xe.html). Если установщик обнаружил уже существующую Oracle, не удаляйте её ради демонстрации: сначала выясните у владельца, можно ли создать схему в ней.

### Linux и macOS

На поддерживаемой Linux можно установить Oracle Free штатным пакетом по [инструкции Oracle для Linux](https://docs.oracle.com/en/database/oracle/oracle-database/26/xeinl/index.html). Установку и запуск службы выполняет администратор системы; пакет не предназначен для произвольного дистрибутива Linux.

Для macOS в этой инструкции используется **Oracle на другом компьютере/сервере**: нативный сервер для macOS не предлагается среди [установщиков Oracle Free](https://www.oracle.com/database/free/get-started/). Сам Qwiz на Python и SQL-клиент запускаются на Mac. На Windows Home/ARM также можно работать с удалённой Oracle вместо установки сервера локально.

### Подключение через DBeaver

1. Создайте новое подключение типа **Oracle**. При первом подключении разрешите скачать драйвер, если DBeaver предложит это.
2. Укажите адрес, порт и **Service name**, а не SID. Для локальной Free: `127.0.0.1`, `1521`, `FREEPDB1`. Для сервера — выданные значения.
3. Если нужно создать новую схему и это разрешено, войдите как `SYSTEM` с паролем, заданным при установке. Для готовой схемы сразу используйте её пользователя.
4. Нажмите «Test Connection / Проверить подключение». До успешной проверки к установке SQL не переходите.

### Создание отдельной демонстрационной схемы

Если схему уже выдали, этот шаг пропустите. Следующий SQL выполняется в SQL-редакторе DBeaver под служебным пользователем с правом создания пользователей, подключённым **к нужной PDB**, не к корневой базе `FREE`:

```sql
SELECT SYS_CONTEXT('USERENV', 'CON_NAME') AS container_name FROM dual;
```

Для локальной Free ожидается `FREEPDB1`. Если возвращается `CDB$ROOT`, исправьте имя сервиса в подключении. Затем в выделенной для демонстрации базе выполните:

```sql
CREATE USER QWIZ_DEMO IDENTIFIED BY QwizLocalDemo2026;
GRANT CREATE SESSION, CREATE TABLE, CREATE SEQUENCE, CREATE TRIGGER, CREATE PROCEDURE TO QWIZ_DEMO;
GRANT UNLIMITED TABLESPACE TO QWIZ_DEMO;
```

Это пример прав для отдельной демосхемы. На общем сервере DBA может выделить ограниченную квоту вместо `UNLIMITED TABLESPACE`. Если прав на создание пользователя нет, передайте SQL администратору базы. Не повторяйте `CREATE USER`, если `QWIZ_DEMO` уже существует, и не удаляйте существующую схему вслепую.

Пароль `QwizLocalDemo2026` — пример только для отдельной демонстрационной схемы. Он не является паролем `SYSTEM` или пользователя сайта.

## 4. Установка таблиц и демонстрационных данных

Этот раздел выполняется один раз только в **новой пустой схеме**, подготовленной в разделе 3. Для существующего Qwiz используйте обновление из раздела 8.

1. Создайте в DBeaver **отдельное подключение как `QWIZ_DEMO`**: тот же адрес, порт и сервис, пароль `QwizLocalDemo2026` из примера. Не используйте подключение `SYSTEM` для установки таблиц приложения.
2. Откройте SQL-редактор именно этого подключения и проверьте пользователя:

```sql
SELECT USER AS schema_user FROM dual;
```

Ожидаемый результат — `QWIZ_DEMO` (или имя отдельной схемы, выданной DBA).

3. Откройте файл проекта `sql/00_install_all.sql` в кодировке **UTF-8**. Проверьте выбранное подключение в редакторе. Включите остановку выполнения при ошибке.
4. Выполните **весь файл как SQL Script**, а не текущую строку: меню «Execute SQL Script», обычно `Alt+X`. Если в редакторе выделен фрагмент, снимите выделение. См. [выполнение скриптов в DBeaver](https://dbeaver.com/docs/dbeaver/SQL-Execution/).
5. В конце две строки `QUIZ_PLATFORM` должны иметь статус **VALID**, а запрос ошибок — вернуть пустой результат. При `INVALID` или ошибках Oracle остановитесь и сохраните первую ошибку.
6. Если нужны готовые пользователи и тест, **только в этой выделенной демонстрационной схеме** выполните таким же способом `sql/08_seed_test_data.sql`.

**Важно:** `08_seed_test_data.sql` удаляет все прежние данные приложения в выбранной схеме, включая пользователей и результаты. Не используйте его для обновления, обычного перезапуска, в общей схеме с нужными результатами или на рабочей базе. Если демоданные не нужны, пропустите шаг 6: первый зарегистрированный пользователь пустой базы получит роль администратора.

Не выполняйте все файлы папки `sql` подряд: установщик `00` уже содержит необходимые таблицы, справочники и пакет. SQL-файлы сохраняйте в UTF-8, не ANSI. При использовании SQL*Plus вместо DBeaver задайте `NLS_LANG=.AL32UTF8` перед запуском клиента.

## 5. Запуск сайта

Откройте обычный терминал в папке проекта. Введите команды для своей системы.

Ниже — пример для новой локальной Oracle Free и демосхемы. Для готовой удалённой базы замените **все три** значения `DB_USER`, `DB_PASSWORD` и `DB_DSN` выданными параметрами. `DB_DSN` имеет формат `адрес:порт/имя_сервиса`; `127.0.0.1` годится только если Oracle находится на том же компьютере.

### Windows — PowerShell

```powershell
$env:DB_USER="QWIZ_DEMO"
$env:DB_PASSWORD="QwizLocalDemo2026"
$env:DB_DSN="127.0.0.1:1521/FREEPDB1"
$env:SECRET_KEY="qwiz-local-demo-session-key-2026"
.\.venv\Scripts\python.exe manage.py check-db
```

### macOS / Linux — Терминал

Для запуска с Mac укажите в `DB_DSN` адрес выданного сервера Oracle вместо `127.0.0.1`. На Linux локальный адрес подходит только если сервер Oracle установлен на этом же компьютере.

```sh
export DB_USER="QWIZ_DEMO"
export DB_PASSWORD="QwizLocalDemo2026"
export DB_DSN="127.0.0.1:1521/FREEPDB1"
export SECRET_KEY="qwiz-local-demo-session-key-2026"
./.venv/bin/python manage.py check-db
```

Ожидаемый ответ: **«Подключение работает. Пакет QUIZ_PLATFORM и таблица таймеров готовы.»**

Если диагностика не прошла, не запускайте сайт вслепую: исправьте подключение или схему по разделу 10.

После успешной диагностики, **в том же окне терминала**:

Windows:

```powershell
.\.venv\Scripts\python.exe -m flask --app app run --host 127.0.0.1 --port 5063
```

macOS/Linux:

```sh
./.venv/bin/python -m flask --app app run --host 127.0.0.1 --port 5063
```

Дождитесь `Running on http://127.0.0.1:5063`, затем откройте **http://127.0.0.1:5063** в браузере. Терминал с приложением оставьте открытым. Предупреждение Flask о development server нормально для этой локальной демонстрации.

Переменные задаются заново в каждом новом терминале. Для прямого запуска `manage.py` приложение не загружает настройки из `.env`; используйте явно показанные переменные. Не полагайтесь на значения подключения, зашитые в `db.py`: они могут относиться к недоступной вам базе.

## 6. Вход и работа с приложением

### Готовые демонстрационные учётные записи

Они появляются **только после выполнения `08_seed_test_data.sql`**:

| Роль | ID пользователя для входа | Пароль |
|---|---|---|
| Администратор | `1000` | `adminpass` |
| Автор тестов | `1001` | `authorpass` |
| Обычный участник | `1002` | `userpass` |

В поле входа вводится числовой ID, а не имя `admin1`, `author1` или `user1`.

Для переключения ролей нажимайте **«Выход»**, затем входите заново. Для одновременной проверки используйте разные браузеры или обычное и приватное окно. Две обычные вкладки одного браузера используют одну сессию: вход во второй вкладке изменит пользователя и в первой.

### Быстрая проверка на готовом тесте

1. Войдите как участник `1002`.
2. Откройте **«Доступные тесты» → «Простой тест»**.
3. Нажмите **«Начать / продолжить попытку»**.
4. Ответьте по очереди: `4`, `5`, `test`. После каждого ответа нажимайте **«Сохранить ответ и продолжить»**.
5. Нажмите **«Завершить попытку»**. Ожидаемый результат: **3 балла, 100%**, ответы и пояснения.
6. Откройте **«Мои попытки»** и убедитесь, что результат есть в истории.

В демонстрационных данных уже есть одна завершённая попытка участника `1002`. У готового теста лимит — 3 попытки; после начальной загрузки у этого участника остаются две новые. Для дальнейшей проверки зарегистрируйте другого участника и выдайте ему доступ либо создайте новый тест. Не очищайте всю базу ради очередного прохождения.

### Создание своего теста под автором

1. Войдите как автор `1001`. В **«Категории»** создайте категорию, например «Проверка приложения».
2. Перейдите в **«Банк вопросов» → «Создать вопрос»**. Заполните текст, категорию, сложность и тип. При необходимости прикрепите изображение PNG, JPEG, GIF или WebP. Максимальный размер всего запроса, включая файл, — 5 МБ.
3. Для числового вопроса укажите правильное число и допуск (`0` — точное совпадение). Для текстового — правильный текст. Текст сравнивается без учёта регистра и пробелов по краям, но не «по смыслу».
4. Для выбора ответа после создания добавьте минимум два варианта и отметьте правильные. Для одиночного выбора — ровно один правильный, для множественного — один или больше. Тип «Верно / неверно» также требует создания вариантов вручную.
5. Откройте **«Тесты автора» → «Создать тест»**. Для первой проверки задайте название, время `600` секунд, лимит `3` попытки и включите обратную связь.
6. На странице теста откройте **«Ручное наполнение вопросами»**. Добавьте вопросы: вес `1`, уникальный порядок `1`, `2`, `3`, обязательность — «Да». Время на вопрос можно оставить пустым. Вес определяет количество баллов, порядок — последовательность показа.
7. Вернитесь к тесту и нажмите **«Опубликовать тест»**. Пустой тест или вопрос без необходимых правильных ответов опубликовать нельзя.
8. Откройте **«Доступ к тесту»**, введите ID участника, например `1002`, и нажмите **«Выдать доступ»**. Одной публикации недостаточно для обычного пользователя.
9. Выйдите из аккаунта автора, войдите участником и пройдите тест. Затем под автором откройте **«Статистика теста»**.

### Автоматическое наполнение

Вместо ручного добавления можно нажать **«Автоматически сформировать тест»**. Для этого в тесте должны быть заданы сложность и плановое количество вопросов, а подходящих готовых вопросов должно хватать. Категория, если выбрана, также ограничивает подбор.

Автор использует свои вопросы, администратор — вопросы всех авторов. Автогенерация **заменяет** текущий состав, а не дополняет его. Она доступна только для скрытого теста, по которому ещё не было попыток. Если вопросов недостаточно, приложение сообщает об этом и сохраняет прежний состав.

### Что важно знать участнику

- Пустой ответ не сохраняется. Необязательный вопрос можно пропустить отдельной кнопкой.
- Обновление страницы не обнуляет время. Выход из страницы не ставит таймер на паузу.
- Повторное нажатие «Начать / продолжить» возвращает в текущую попытку, если она ещё активна.
- Сохранённые ответы нельзя редактировать задним числом.
- Кнопка завершения становится доступна после обязательных вопросов. По истечении времени завершение выполняется автоматически, пока страница открыта; если страница закрыта, просрочка обрабатывается при следующем обращении к попытке. Отдельного фонового планировщика завершения здесь нет.
- Ответ за пределами времени на вопрос получает 0 баллов. При истечении общего времени уже сохранённые ответы учитываются.
- Обратная связь зависит от настройки теста. Отсутствие эталонов при отключённой обратной связи — ожидаемое поведение.

### Возможности администратора

Администратор видит меню управления всеми тестами, вопросами, пользователями, категориями, попытками и общей статистикой. Он может управлять объектами других авторов, назначать роли, выдавать и отключать доступ, публиковать и скрывать тесты, использовать общий банк вопросов.

В **«Админ: пользователи»** выберите роль нужного пользователя и нажмите **«Сохранить роль»**. Для нового пользователя сначала выполните обычную регистрацию: пароль — минимум 4 символа. Запишите выданный ID. В чистой базе без демоданных первый зарегистрированный пользователь становится администратором; остальные — обычными пользователями.

Администратор может проходить любой готовый тест, включая скрытый, без выдачи доступа и лимита количества попыток. Это **не безопасный предпросмотр**: прохождение создаёт настоящую попытку, влияет на статистику и фиксирует состав теста.

Раздел **«Админ: все попытки»** позволяет открыть попытки любого участника. В незавершённой чужой попытке показывается предупреждение: сохранение ответов и завершение изменят результат именно этого участника. Для обычного ознакомления пользуйтесь уже завершёнными результатами. Администратор видит обратную связь и при отключённом показе для участников.

### Ограничения, которые не являются ошибками

- После **первого начала попытки**, даже незавершённой, состав теста фиксируется для всех ролей. Для изменённого набора создайте новый тест.
- В опубликованном тесте без попыток сначала нажмите «Скрыть тест», затем меняйте состав.
- Варианты вопроса нельзя менять, если он используется в опубликованном тесте или тесте с попытками.
- Администратор не может снять роль администратора у самого себя.
- Готовый «Простой тест» уже содержит завершённую попытку, поэтому не подходит для проверки редактирования состава. Создайте отдельный новый тест.

## 7. Остановка и повторный запуск

### Остановка

1. В терминале, где работает Flask, нажмите `Ctrl+C`.
2. Обычно Oracle можно оставить работающей как службу. Останавливать общую или рабочую базу ради закрытия своего сайта не нужно. Собственную локальную Oracle при необходимости останавливает ответственный за установку средствами ОС.

Остановка Flask не удаляет результаты: они хранятся в Oracle. Не удаляйте схему или файлы базы. Загруженные изображения находятся отдельно, в папке проекта `static/uploads/questions`: её тоже нужно сохранять.

### Повторный запуск после закрытия терминала или перезагрузки

1. Если Oracle удалённая, проверьте подключение к нужной сети/VPN. Если локальная, убедитесь, что её службы запущены; в Windows их можно посмотреть в приложении «Службы» (`services.msc`). Нужны служба базы и её listener. Не меняйте службы других установок Oracle.
2. В папке проекта повторите **раздел 5**: переменные подключения, диагностику и запуск Flask. Успешный `manage.py check-db` подтверждает, что нужная схема доступна.
3. Откройте сайт в браузере.

Не создавайте повторно пользователя Oracle, не запускайте установщик и не загружайте демоданные при обычном перезапуске. Зависимости повторно устанавливают, только если изменился `requirements.txt` или создано новое окружение.

## 8. Подключение к существующей Oracle и обновление

Получите у ответственного за базу: адрес, порт, **имя сервиса**, имя пользователя схемы и пароль. При необходимости подключите VPN/сеть, в которой доступна база. Если схема Qwiz уже обновлена, проверяющему достаточно разделов 2 и 5 — самостоятельно переустанавливать её не нужно.

Не путайте пользователя базы данных (`DB_USER`) с числовым ID участника на сайте. Также не подменяйте имя сервиса SID: в приведённом формате подключения используется именно имя сервиса.

1. Выполните подготовку Python из раздела 2.
2. Определите состояние схемы. Для **новой пустой** схемы используется только `sql/00_install_all.sql`; для **ранее установленного Qwiz** — `sql/10_upgrade_workflow.sql`. Нового пользователя схемы и права создаёт администратор Oracle, если их ещё нет.
3. Перед обновлением остановите все экземпляры приложения, подключённые к этой схеме, и согласуйте резервную копию данных с владельцем базы.
4. В DBeaver подключитесь под тем пользователем, который затем будет указан в `DB_USER`. Откройте выбранный SQL-файл в UTF-8 и выполните **весь скрипт** через «Execute SQL Script» (обычно `Alt+X`), а не одну текущую строку. Включите остановку при ошибке.
5. В конце обе строки пакета `QUIZ_PLATFORM` должны быть `VALID`, а запрос ошибок — пустым. При ошибке не продолжайте следующие шаги.
6. В командах раздела 5 замените значения `DB_USER`, `DB_PASSWORD`, `DB_DSN` своими. Формат DSN: `адрес:порт/имя_сервиса`. Задайте свою постоянную строку `SECRET_KEY` для этого экземпляра приложения.
7. Выполните `manage.py check-db`, затем запустите сайт той же командой Flask на порту `5063`.

Обновление `10_upgrade_workflow.sql` сохраняет пользователей, тесты и результаты и может выполняться повторно при остановленном приложении. В рабочей схеме **никогда не запускайте** `08_seed_test_data.sql` и `99_drop_all.sql`: они удаляют данные/объекты. Не запускайте все SQL-файлы подряд по номерам.

Учётные записи `1000`–`1002` и пароли из раздела 6 в существующей базе могут отсутствовать. Используйте выданную учётную запись или регистрацию. Если администраторов нет, ответственный за установку может назначить роль уже зарегистрированному активному пользователю:

Windows:

```powershell
.\.venv\Scripts\python.exe manage.py make-admin 1234
```

macOS/Linux:

```sh
./.venv/bin/python manage.py make-admin 1234
```

`1234` замените реальным ID. Это изменение роли в базе, а не команда входа или восстановления пароля. Выполняйте её только для нужного пользователя и после проверки переменных подключения.

## 9. Как передать проект другому человеку

Передайте всю папку исходников вместе с этой инструкцией и [чек-листом тестирования](TEST_CHECKLIST_RU.md). Не передавайте своё Python-окружение `.venv`/`venv`, личные пароли и конфигурации подключения к рабочим системам.

Для простого запуска выдайте получателю параметры **уже подготовленной** схемы Oracle и учётную запись сайта. Тогда он устанавливает только Python-зависимости и запускает Flask. Если каждый проверяющий должен иметь независимые данные, администратор базы заранее создаёт отдельную схему для каждого, устанавливает Qwiz и передаёт соответствующие параметры. Не предлагайте всем по очереди запускать очистку одной общей схемы.

Архив с исходниками не содержит содержимое Oracle. Если передаются существующие вопросы с картинками, нужны и данные базы, и соответствующая папка `static/uploads/questions`. Пересылайте параметры разрешённым способом отдельно от общедоступного архива.

## 10. Частые проблемы

| Что видно | Причина и действие |
|---|---|
| `{{ ... }}`, `{% ... %}`, «РўРµ…» вместо текста | Открыт исходный файл. Запустите Flask и откройте `http://127.0.0.1:5063`, не `file://...`. |
| Браузер не может подключиться | Flask не запущен или остановился. Проверьте терминал и строку `Running on`. На другом компьютере `127.0.0.1` указывает не на ваш сервер. |
| `Address already in use` / порт занят | Возможно, Qwiz уже запущен: сначала откройте адрес. Если порт занят другой программой, не завершайте её вслепую; запустите Flask с `--port 5064` и откройте этот порт. Порт 5000 на macOS может быть занят системной службой, поэтому здесь используется 5063. |
| DBeaver установлен, но к базе не подключается | DBeaver — клиент, а не сама Oracle. Нужен работающий локальный/удалённый сервер и верные параметры из раздела 3. |
| Установщик Oracle не поддерживает Windows или обнаруживает прежнюю установку | Сверьте редакцию Windows и архитектуру с требованиями из раздела 3. Не удаляйте существующую Oracle; используйте её с разрешения владельца либо подключитесь к подготовленному серверу. |
| На Mac нет установщика сервера Oracle | Используйте Oracle на другом компьютере/сервере. Само Python-приложение запускается на Mac; в `DB_DSN` нужен адрес сервера, не `127.0.0.1`. |
| `ORA-65096` при создании пользователя | Для Oracle Free проверьте подключение к `FREEPDB1`, не к `CDB$ROOT`. Если схема выдаётся организацией, её создание поручите DBA. |
| `ORA-01031` / недостаточно прав | Подключение успешно, но прав на установку объектов или создание пользователя нет. Попросите DBA подготовить отдельную схему и выдать права из раздела 3. |
| `python`/`py`/`python3` не найден | Установите Python, откройте новый терминал и повторите проверку версии. На Windows попробуйте `py -3`, на macOS/Linux — `python3`. |
| `No module named flask/oracledb` | Используется не то окружение или зависимости не установлены. Повторите установку через Python именно из `.venv`, как в разделе 2. |
| `ensurepip`/`venv` недоступен на Linux | Установите пакет поддержки `venv` для своей версии Python средствами дистрибутива, затем создайте окружение заново. |
| `check-db` не прошёл / страница сообщает об ошибке базы | Проверьте все три переменные подключения в текущем терминале, доступность Oracle и готовность сервиса. В примере локальной Free: `QWIZ_DEMO`, порт `1521`, сервис `FREEPDB1`; реальные значения берутся из установки или у DBA. Для внешней базы может быть нужен VPN. |
| Схема требует обновления / пакет `INVALID` / не найдена таблица | Проверьте, под каким пользователем выполнен SQL. Для существующего Qwiz выполните обновление `10` и посмотрите первую ошибку. Для пустой схемы нужен установщик `00`. |
| `ORA-00955` при установке | Объект уже существует: вероятно, схема не пустая или установка уже выполнялась. Не удаляйте таблицы наугад; выясните состояние схемы и используйте обновление для существующего Qwiz. |
| Русский текст из базы испорчен даже через HTTP | Проверьте кодировку SQL при загрузке данных. Файлы должны быть UTF-8, SQL*Plus — с `NLS_LANG=.AL32UTF8`. Если испорченные строки уже записаны в рабочую БД, её нельзя «лечить» запуском очистки демоданных: нужна отдельная корректировка данных. |
| Не удаётся войти под `admin1` | Для входа нужен числовой ID `1000`, а не имя. Демопароль `adminpass` работает только в схеме с загруженными демоданными. |
| У участника пустой список тестов | Проверьте публикацию теста и выдачу доступа именно его ID. Администратору отдельная выдача доступа не нужна. |
| «Превышен лимит попыток» | Для обычного участника лимит действует. Возобновите незавершённую попытку либо используйте нового участника/новый тест. |
| Нельзя изменить состав или варианты | Проверьте ограничения из раздела 6: публикацию и наличие хотя бы одной попытки. Это защита результатов, а не ошибка прав администратора. |
| Не получается сохранить пустой ответ или закончить тест раньше | Заполните ответ или используйте «Пропустить вопрос» для необязательного. Сначала нужно пройти обязательные вопросы. |
| Изображение не загрузилось | Проверьте расширение, общий размер запроса до 5 МБ и право записи в `static/uploads/questions`. При ошибке формы файл нужно выбрать повторно. |

Если проблему не удалось решить, используйте шаблон сообщения об ошибке в [чек-листе](TEST_CHECKLIST_RU.md). Пароли, секретные ключи и полные строки подключения в сообщение не включайте.
