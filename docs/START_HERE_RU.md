# Qwiz: как запустить и проверить приложение

Нужны папка проекта, **Python 3.10+**, браузер и доступ к серверу Oracle.
Docker, локальный сервер Oracle и отдельный установщик не нужны.
Если адрес базы доступен только в сети организации — подключитесь к этой сети или её VPN.

## 1. Подключение к базе уже настроено

В `db.py` указаны:

| Параметр | Значение |
| --- | --- |
| Сервер | `10.22.10.40` |
| Порт | `1521` |
| Тип подключения | **SID** |
| SID | `ORCL` |
| Пользователь | `KE2302_07` |
| Пароль | `KE2302_07` |

Ничего дополнительно задавать для запуска не нужно. `db.py` используется и сайтом,
и командой проверки базы. В нём SID передаётся явно через `oracledb.makedsn(..., sid="ORCL")`.
Не заменяйте это строкой `10.22.10.40:1521/ORCL`: в таком формате `ORCL` означает имя сервиса.

Все, кто использует эти реквизиты, работают с **одной общей схемой**. Изменения вопросов,
тестов и результатов видны другим проверяющим. Не очищайте общую базу.

## 2. Подготовьте Python и запустите сайт

Откройте терминал **в папке проекта**, где находится `app.py`.
Не используйте чужую папку `venv`/`.venv`: создайте своё окружение следующими командами.

### Windows — PowerShell

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe manage.py check-db
.\.venv\Scripts\python.exe -m flask --app app run --host 127.0.0.1 --port 5063
```

Если `py` не найден, установите Python или используйте `python -m venv .venv`,
если команда `python --version` уже работает и показывает версию 3.10 или новее.

### macOS / Linux

```sh
python3 -m venv .venv
./.venv/bin/python -m pip install -r requirements.txt
./.venv/bin/python manage.py check-db
./.venv/bin/python -m flask --app app run --host 127.0.0.1 --port 5063
```

Выполняйте команды по очереди. Если `check-db` сообщает об ошибке, сначала исправьте
подключение или подготовьте схему по разделу 3. Успешная проверка сообщает, что подключение
работает, пакет Qwiz и таблица таймеров готовы.

Откройте **http://127.0.0.1:5063**. Не открывайте HTML-файлы из `templates` напрямую.
Терминал должен оставаться открытым. Для остановки нажмите **Ctrl+C**.
Для повторного запуска выполните только последнюю команду из своего блока —
переустанавливать зависимости и пересоздавать базу не нужно.

## 3. Если схема ещё не готова

Этот раздел выполняет **один ответственный за базу**, не каждый проверяющий.
При запуске сайта таблицы и пакет **автоматически не создаются**.

1. В DBeaver создайте подключение Oracle с параметрами из раздела 1.
   Выберите **SID**, а не Service name; роль подключения — обычная, не SYSDBA.
2. Убедитесь, что открыта схема **`KE2302_07`**.
3. Если схема пустая, откройте `sql/00_install_all.sql` в UTF-8.
   Если в ней уже установлена прежняя версия Qwiz — используйте `sql/10_upgrade_workflow.sql`.
   Если объекты неизвестны или установка ранее оборвалась, сначала разберитесь с ответственным
   за базу: не запускайте новую установку поверх существующих таблиц.
4. Выполните **весь файл как SQL Script** (в DBeaver обычно `Alt+X`), а не одну строку.
   Включите остановку выполнения при ошибке. Не продолжайте после ошибки прав или создания объекта.
5. В итоговой проверке пакет и тело `QUIZ_PLATFORM` должны иметь статус `VALID`,
   а список ошибок компиляции — быть пустым. Затем повторите `manage.py check-db`.

Для установки у `KE2302_07` должны быть права создания таблиц, последовательностей,
триггеров и процедур, а также квота на место в базе. Если их нет — обратитесь к администратору Oracle.
Перед обновлением остановите все экземпляры Qwiz, работающие с этой общей схемой.
Обновление `10` сохраняет данные, но перед ним рекомендуется резервная копия.

**Не запускайте `08_seed_test_data.sql` и `99_drop_all.sql` в общей схеме:**
они удаляют данные. Демонстрационные логины не появляются при обычной установке `00`.

## 4. Как пользоваться приложением

1. Зарегистрируйте пользователя и сохраните показанный **числовой UID**.
   Первый пользователь пустой базы автоматически становится администратором.
2. Войдите по UID и своему паролю. `KE2302_07` — учётная запись Oracle, не логин сайта.
3. Администратором откройте раздел пользователей и назначьте нужному участнику роль автора.
4. Автором или администратором создайте категорию, вопрос с правильным ответом и скрытый тест.
   Добавьте в тест готовые вопросы, затем опубликуйте его.
5. Выдайте доступ обычному пользователю по UID. В отдельном браузере или приватном окне
   войдите этим пользователем, откройте «Доступные тесты», пройдите тест и посмотрите результат.
6. Проверьте историю попыток, статистику и отображение загруженной картинки вопроса.

Администратор управляет вопросами, тестами и попытками всех авторов и может проходить
готовые скрытые тесты без отдельной выдачи доступа. Таймеры и ограничения на изменение
уже начатых тестов действуют и для него — это сохраняет корректность результатов.

Если пользователи уже есть, а администратора нет, ответственный за приложение может
назначить зарегистрированного пользователя, заменив `1234` на его UID:

```powershell
.\.venv\Scripts\python.exe manage.py make-admin 1234
```

На macOS/Linux используйте `./.venv/bin/python manage.py make-admin 1234`.
Подробные сценарии — в [чек-листе тестирования](TEST_CHECKLIST_RU.md).

## 5. Частые проблемы

| Проблема | Что сделать |
| --- | --- |
| Тайм-аут подключения к Oracle | Проверьте сеть/VPN и доступ к `10.22.10.40:1521`. Сам сайт не запускает удалённый сервер Oracle. |
| Ошибка SID / listener | Проверьте, что используется именно SID `ORCL` и настройки из `db.py`. |
| Неверный пользователь или пароль Oracle | Проверьте `KE2302_07` / `KE2302_07`; при блокировке учётной записи обратитесь к администратору базы. |
| Настройки правильные, но подключается к другой базе | Старые переменные окружения `DB_USER`, `DB_PASSWORD`, `DB_DSN` переопределяют `db.py`. Удалите их или откройте терминал без этих настроек. |
| Нет таблиц / пакет не работает | Выполните проверку `manage.py check-db` и раздел 3. |
| В браузере `{{ ... }}` или `{% ... %}` | Открыт файл шаблона. Перейдите на `http://127.0.0.1:5063`. |
| Порт занят | Возможно, сайт уже работает. Либо запустите с `--port 5064` и откройте `http://127.0.0.1:5064`. |
| После закрытия терминала сайт недоступен | Запустите его снова последней командой из раздела 2. Данные Oracle сохраняются. |

Изображения сохраняются в `static/uploads/questions`, остальные данные — в Oracle.
Не удаляйте папку изображений, если они ещё нужны в вопросах.
