# Qwiz: чек-лист проверки работоспособности

Сначала выполните [инструкцию по запуску без Docker](START_HERE_RU.md). Проверки с созданием данных проводите в отдельной демонстрационной схеме установленной локально или доступной по сети Oracle. Не запускайте очистку рабочей базы ради тестирования.

## Подготовка

- [ ] Oracle и Flask запущены; `manage.py check-db` сообщает об успешном подключении и готовой схеме.
- [ ] Сайт открыт через `http://127.0.0.1:5063`, а не через HTML-файл.
- [ ] Есть три роли: администратор, автор и участник. В демо это ID `1000` / `1001` / `1002`, пароли `adminpass` / `authorpass` / `userpass`.
- [ ] Для разных ролей используются разные сеансы браузера или явный выход и повторный вход.
- [ ] Для редактирования создаётся **новый тест**: готовый «Простой тест» уже содержит попытку и не допускает изменения состава.

## 1. Базовые сценарии

| Проверка | Действия | Ожидаемый результат |
|---|---|---|
| Вход | Войти по ID и верному паролю, затем проверить неверный пароль | Верный вход открывает кабинет с ID и ролью; неверный показывает сообщение, без падения страницы. |
| Регистрация | Создать участника, записать выданный ID, войти по нему | Новый пользователь появляется в списке администратора; его данные видны в профиле. |
| Роль | Администратором назначить новому пользователю AUTHOR | После обновления страницы этому пользователю доступны банк вопросов и тесты автора. |
| Создание вопроса | Автором создать вопрос с категорией, сложностью и корректным эталоном/вариантами | Вопрос появляется в банке и открывается без ошибок. |
| Картинка | Создать вопрос с небольшим PNG/JPEG | Изображение видно в карточке вопроса и при прохождении. |
| Создание теста | Создать скрытый тест и вручную добавить вопросы с разным порядком | Состав и порядок отображаются правильно; число вопросов соответствует фактическому составу. |
| Удаление из черновика | Убрать вопрос из нового скрытого теста без попыток | Вопрос исчезает из состава, но остаётся в банке. |
| Варианты | В вопросе, не используемом в опубликованных/начатых тестах, добавить и удалить вариант | Список обновляется; одиночный выбор не допускает второй правильный вариант. |
| Публикация | Попытаться опубликовать пустой/неготовый тест, затем исправить и опубликовать | В первом случае понятная ошибка; во втором — статус «Опубликован». |
| Выдача доступа | Выдать опубликованный тест конкретному ID | Участник видит тест в «Доступных тестах»; другой участник без доступа не видит. |
| Прохождение | Ответить на все обязательные вопросы и завершить | Ответы сохраняются, появляется конечный статус, баллы и процент. |
| История и статистика | Открыть «Мои попытки», затем статистику под автором | Есть завершённая попытка и соответствующие показатели. |

## 2. Типы вопросов и оценки

Для предсказуемого результата создайте новый тест из шести обязательных вопросов с весом `1`, временем теста `600` секунд, без отдельных лимитов на вопросы и с включённой обратной связью.

| Тип | Пример задания и эталона | Ответ для проверки |
|---|---|---|
| Один правильный ответ | «2 + 2?»; варианты `4` — правильный, `3` — неправильный | Выбрать `4`. |
| Несколько правильных ответов | «Выберите чётные»; `2` и `4` — правильные, `3` — неправильный | Выбрать только `2` и `4`. |
| Текстовый ответ | «Введите слово test»; эталон `test` | Ввести ` TEST `: регистр и пробелы по краям не должны мешать. |
| Числовой ответ | «10 / 2?»; эталон `5`, допуск `0` | Ввести `5`. |
| Верно / неверно | «2 + 2 = 4»; добавить варианты «Верно» — правильный, «Неверно» — неправильный | Выбрать «Верно». |
| Короткий ответ | «Столица Франции?»; эталон `Париж` | Ввести `Париж`. |

- [ ] Все шесть правильных ответов дают **6 баллов и 100%**.
- [ ] В новом тесте из двух обычных текстовых вопросов с весом `1`, один верный и один неверный ответ дают **1 балл и 50%**.
- [ ] В новом тесте с одним верно отвеченным вопросом весом `2.5` результат — **2.5 балла и 100%**.
- [ ] Если обратная связь отключена, участник не видит эталоны, но администратор видит ответы в результате.

## 3. Пограничные сценарии

Каждый сценарий, где нужны другие настройки, выполняйте на новом тесте. Не меняйте структуру уже начатого теста.

| Проверка | Действия | Ожидаемый результат |
|---|---|---|
| Пустой ответ | Нажать сохранение без ответа | Форма не пропускает дальше; вопрос не считается отвеченным. |
| Необязательный вопрос | Установить «Обязательный: Нет» и при прохождении нажать «Пропустить вопрос» | Можно перейти дальше; пропуск не даёт баллов. |
| Повторный старт | Начать тест, вернуться к его странице и снова нажать старт | Продолжается та же активная попытка, а не создаётся новая. |
| Лимит попыток | Обычным участником завершить тест с лимитом `1` и попробовать начать заново | Новая попытка не создаётся; показано сообщение о лимите. Для ADMIN лимит не действует. |
| Время на вопрос | Новый тест: общее время `120` секунд, на вопрос `10` секунд. Начать, через несколько секунд обновить страницу, дождаться конца | Время не начинается заново; после истечения вопрос пропускается автоматически и получает 0 баллов. |
| Общее время | Новый тест: общее время `15` секунд, минимум два вопроса. Сохранить первый, на втором дождаться конца | Открытая страница завершает попытку со статусом «Время истекло»; сохранённый ответ учитывается. |
| Автогенерация | Создать достаточно готовых вопросов нужной сложности и категории; сгенерировать новый скрытый тест | Получено заданное число вопросов. Автор использует свои вопросы, администратор — общий банк. |
| Недостаточно вопросов | Создать новый тест с планом больше подходящего банка; добавить один вопрос вручную и запустить генерацию | Понятное сообщение, прежний состав не потерян. |
| Защита результатов | Начать попытку и попробовать изменить состав теста или варианты его вопросов | Изменение не разрешается, старые ответы и результаты остаются корректными. |

## 4. Права администратора

- [ ] Из «Админ: тесты» открываются тест, доступ и статистика другого автора.
- [ ] В чужом **скрытом тесте без попыток** администратор может менять состав, генерировать вопросы, затем публиковать/скрывать тест и управлять доступами.
- [ ] Из «Админ: вопросы» открывается чужой вопрос; варианты доступны для изменения, если нет ограничений по публикации/попыткам.
- [ ] Готовый скрытый тест доступен администратору для прохождения без выдачи доступа. Помните: это настоящая попытка, фиксирующая состав.
- [ ] «Админ: все попытки» показывает участников и их результаты. В чужой незавершённой попытке есть предупреждение о действиях от имени участника.
- [ ] Проверка продолжения чужой попытки выполняется только на специально созданной тестовой учётной записи, не на реальных ответах человека.
- [ ] Автор без роли ADMIN не может открыть управление тестом другого автора. Обычный участник не может открыть административные разделы.

## 5. Автоматические проверки — для ответственного за установку

### Без базы Oracle

Из корня проекта:

Windows:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe scripts/build_sql.py --check
```

macOS/Linux:

```sh
./.venv/bin/python -m unittest discover -s tests -v
./.venv/bin/python scripts/build_sql.py --check
```

Переменная `QWIZ_TEST_DSN` для этого запуска должна быть **не задана**. Будут выполнены проверки без БД, а сценарии Oracle помечены `skipped` — в таком режиме это нормально. Успешный запуск с пропусками не означает, что проверена вся работа с Oracle.

### Полная проверка с Oracle

Нужна отдельная **одноразовая** схема с именем `QWIZ_TEST`, созданная администратором Oracle в базе, предназначенной для тестирования. Права и порядок установки такие же, как для `QWIZ_DEMO` в основной инструкции, но пользователь называется `QWIZ_TEST`. В пустой схеме сначала выполните `sql/00_install_all.sql`; демоданные `08` не нужны.

**Тесты удаляют записи приложения в QWIZ_TEST перед каждым сценарием.** Не переименовывайте рабочую схему в QWIZ_TEST и не используйте эту схему для ручной демонстрации или хранения нужных данных. `QWIZ_TEST_DSN` и `QWIZ_TEST_PASSWORD` — параметры этой одноразовой базы, а не рабочего приложения.

Windows — замените адрес и пароль действительными значениями тестовой схемы:

```powershell
$env:QWIZ_TEST_DSN="127.0.0.1:1521/FREEPDB1"
$env:QWIZ_TEST_PASSWORD="ПАРОЛЬ_СХЕМЫ_QWIZ_TEST"
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

macOS/Linux:

```sh
QWIZ_TEST_DSN="127.0.0.1:1521/FREEPDB1" QWIZ_TEST_PASSWORD="ПАРОЛЬ_СХЕМЫ_QWIZ_TEST" ./.venv/bin/python -m unittest discover -s tests -v
```

`127.0.0.1:1521/FREEPDB1` — пример для локальной Oracle Free. Для удалённой базы, в том числе при запуске Python на Mac, замените его выданным `адрес:порт/имя_сервиса`.

Для текущей версии ожидаются **32 проверки, OK, без пропусков и ошибок**. Число может измениться при добавлении новых тестов. Windows-переменные после проверки можно убрать закрытием этого терминала, чтобы случайно не запустить удаляющие данные тесты повторно.

## 6. Что приложить к сообщению об ошибке

Скопируйте и заполните:

```text
Версия/дата полученного проекта:
Система: Windows / macOS / Linux, версия:
Браузер:
База: отдельная демо / другая тестовая / рабочая (без пароля):
Роль и ID пользователя:
Адрес страницы:
ID теста / попытки / вопроса:
Действия по шагам:
Ожидаемый результат:
Фактический результат:
Точный текст ошибки:
Повторяется после обновления страницы: да / нет:
```

Добавьте снимок экрана и первую относящуюся к сбою ошибку из терминала Flask или SQL-клиента. Не прикладывайте пароли, `SECRET_KEY`, содержимое сессионных cookie или чужие персональные данные. До выяснения причины не удаляйте схему/файлы базы и не перезагружайте демонстрационные данные: это уничтожит полезную историю воспроизведения.
